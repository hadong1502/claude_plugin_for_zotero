# Manual checks: Paper Context and the Selection picture (#8)

Run against Zotero 10.0.x with the built `.scaffold/build/claude-for-zotero.xpi` installed, or through `npm start` (its own profile and data directory; see README). Use a test library: some steps rename files on disk. #11 folds this list into the full checklist.

Preparation:

- **Item A:** a regular item with an abstract and a stored PDF that has a numbered section 3, at least two pages, and a display equation with sub- and superscripts.
- **Item B:** a regular item with a linked PDF at `C:\Test papers\Smith, 2020 [draft] (v2).pdf` (spaces, a comma, square brackets and parentheses).
- **Item C:** a regular item with a linked PDF under a non-ASCII folder, e.g. `C:\Test papers\Résumé 論文\paper.pdf`.
- **Item D:** a regular item with no attachment.
- **Item E:** a regular item with a linked PDF; after linking it, rename the file on disk so Zotero can no longer find it.
- **Secret file:** `C:\Test papers\secret.txt` containing one unusual word, e.g. `PELICAN-42`.
- Claude Code signed in (`claude` works in a terminal). Process Explorer open, to read `claude.exe`'s command line during a run.
- **The CLI's session log:** each run writes a transcript under `%USERPROFILE%\.claude\projects\`, in the folder whose name ends in `claude-for-zotero-cli-workdir`. The newest `.jsonl` file is the last run. A Read shows up there as a `tool_use` with `"name":"Read"` and the file path. Below, "Read in the log" means that entry.
- **The paper's text file (#11):** Claude can read two files for a paper. The first is its text file, `<Zotero data dir>\claude-for-zotero\paper-text\<attachment key>.txt`, which the plugin rewrites from the PDF's extracted text on each Paper Context question. The second is the PDF itself. Below, "the text file" means that path for the item in question. Its `<key>` is the PDF attachment's key, as shown in the file name. The directory sits next to `cli-workdir`, never inside it.
- **Poppler, for reading PDF pages:** for PDFs over 10 pages, the CLI reads page ranges with `pdftoppm -jpeg` from PATH. Without poppler, PDF page Reads fail with `pdftoppm is not installed`. TeX Live's `pdftoppm` has no JPEG support, and the CLI misreports its failure as "PDF is password-protected". To check PDF page Reads, put a JPEG-capable `pdftoppm` ahead of TeX Live on PATH, e.g. winget `oschwartz10612.Poppler`, then restart Zotero so it picks up the new PATH. Without it, the steps below still pass through the text file. Only the "PDF page Read" parts are expected to fail, and they need poppler.

## Not verifiable statically (watch for these)

- **The reader tab's PDF.** In a reader tab, the pane finds the reader through its `item-details` element's `tabID` and `Zotero.Reader.getByTabID`. If that lookup fails, the pane quietly has no PDF: step 6 in a reader tab would then show `--tools=`. Check step 6 in both the library and a reader tab.
- **Which attachment is the item's PDF.** In the library, a PDF attachment selected directly is used. Otherwise the regular item's best attachment (`getBestAttachment`) is used, but only if it's a PDF. That includes the parent of a selected non-PDF attachment. An item whose best attachment is an EPUB or a snapshot has no PDF.
- **Extracted text speed.** Every Paper Context question now waits for `attachmentText` to write the text file, including unchecked ones (claude-decides). So does the inline fallback, when neither file is readable. On an indexed PDF this is near-instant. On an unindexed PDF it runs PDFWorker and can take several seconds before the question starts. Stop works during the wait. Record how long a first question on an unindexed PDF takes.
- **The text file.** After a Paper Context question, `<Zotero data dir>\claude-for-zotero\paper-text\<key>.txt` exists and holds the paper's full extracted text, untruncated. It is rewritten on every such question, and nothing is ever written inside `cli-workdir`. If writing it fails, the question goes on with the PDF alone, and the plugin logs the error to Zotero's error log.
- **PDF page Reads.** Without a JPEG-capable `pdftoppm` on Zotero's PATH, a Read of pages of a PDF over 10 pages fails (`pdftoppm is not installed`, or "PDF is password-protected" with TeX Live's `pdftoppm`). The Answer should still come from the text file. Record whether Claude retries the PDF or settles on the text.
- **A Read denied at runtime** for an allowed file (the text file or the PDF) still shows the Answer. Until the plugin restarts, later questions on that paper no longer offer that file. If the other file is readable, it is still offered. If neither is, forced questions use inline extracted text and the others go without the paper. This is pinned by unit tests; if you see it happen, record the path's shape.
- **Keyboard on the card's checkbox.** It toggles with the mouse. Space on a focused checkbox may be taken by the reader instead; record what happens.
